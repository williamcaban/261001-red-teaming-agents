Next. Before the pipeline, two design principles that shrink the attack surface.

Design principle for agent architecture

An agent should hold at most two of three powers

  • Untrusted input. Web pages, issues, dependencies, tool results.
  • Sensitive access. Private data, credentials, internal systems.
  • Outward action. State changes, messages, network calls.
Need all three in one session? Put a human approval or a validation step in the path. That step cannot depend on the model's own judgment.

Simon Willison named the combination the lethal trifecta (June 2025). Meta's Agents Rule of Two (October 2025) turns it into a design constraint.

Say. Three powers: untrusted input, sensitive access, outward action. Any two are manageable. All three in one session is the dangerous combination: an attacker plants text, the agent reads it, and the agent has both the data and a way out.

Ask the room. Which of your agents hold all three? Most coding agents do by default. They read issues and repos, hold tokens, and run network commands.

Say. The fix is to remove one power per session, or put in a gate that does not rely on the model. A research agent loses outward action. A browsing agent loses sensitive access.

If asked. 'Isn't a human gate just click fatigue?' It is if it fires often. Gate only rare, high-impact actions, and show the exact action and the data involved.

Source. Simon Willison named the lethal trifecta in June 2025. Meta published the Agents Rule of Two in October 2025.

Next. A structural pattern that enforces this.

Architecture pattern

Read with one model, act with another

Pattern from CaMeL (Google DeepMind, 2025). Untrusted text can change a plan's values, never the plan. Example policy: a value from an email cannot become the recipient of a send action.

Optional. Skip if you are short on time. The talk still works without it.

Say. This is the strongest structural defense in the literature, and it works by construction, not by detection. A planner sees only the trusted user request and writes the plan. A quarantined model reads untrusted data but has no tools. An interpreter runs the plan, tracks where each value came from, and applies policy at every call.

Result. Injected text can change values. It cannot change the plan. Example: a value that came from an email cannot become the recipient of a send action.

Be honest about the cost. You give up agents that rewrite their own plan based on what they read.

Next. The controls you put in place.

What guardrails are in place?

Four types, rigid rules to flexible judgment

Pattern matching

Regex-based. Catches predictable data: SSNs, credit cards, account numbers. Instant redaction.

Algorithmic

Code-based logic: JSON schema validation, token limits, output structure checks.

Guardian models

Small classifiers alongside the main model. Catch jailbreaks, toxic content, prompt injections.

Vector-based

Converts input to embeddings, measures semantic distance from unsafe topics. Keeps a domain system on-topic.

Layer more than one type. No single type catches everything on its own.

Say. Four types, from rigid to flexible. Pattern matching is regex: instant, precise for known formats like SSNs and card numbers. Algorithmic is code-based: schema validation, token limits, structure checks. Guardian models are small classifiers beside the main model for jailbreaks, toxicity, and injections. Vector-based converts input to embeddings and measures distance from unsafe topics.

Say. No single type catches everything. Layer more than one.

Who owns which control

Next. How the adaptive attacks actually work.

Adaptive red teaming

Escalate when the defense holds, stop when it breaks

One classifier scores every response the same way, so strategies stay comparable. The last rung uses a challenger model that rewrites the prompt from the target's refusals. garak (atkgen, TAP-style probes) and promptfoo (iterative and tree strategies) implement this family.

Say. A static prompt list tests the easiest attacks. Adaptive campaigns use the target's answers as feedback.

Walk the loop. Each prompt starts at baseline and moves up a rung only if the target refused or deflected. A compliant answer stops the escalation and counts as a success.

Say. The result is the hardest attack your system currently needs to survive, plus the exact rung where defenses give out. The single classifier matters: without it, strategy-to-strategy comparisons are noise.

Source. garak has atkgen and TAP-style probes. promptfoo has iterative and tree strategies. Both implement this family.

Next. Where to put the boundary.

Where is the boundary?

Three ways to sandbox a harness

Credentials should never live inside the sandbox. Inject them at the network boundary so a hijacked agent has nothing to exfiltrate. The third mode is the cheapest to adopt and the weakest.

Say. Three places to put a sandbox, with three different failure domains.

Left. The whole harness runs inside one boundary. Nothing it does escapes. This is the usual choice for laptops and CI.

Middle. The agent loop runs on a platform and each execution step gets a disposable sandbox. The agent can survive an execution failure, and execution never sees agent state.

Right. The loop runs with full access and only generated code is isolated. Many frameworks stop here. If the loop is hijacked, the host is exposed.

Credentials. Never inside the sandbox. A proxy can substitute real values on outbound requests so the sandbox holds only placeholders. Claude Code's sandbox proxy supports credential masking like this, and OpenShell injects keys at the boundary.

Takeaways

Four things to take with you

  • Agentic attacks live in the trajectory, not the prompt. Test the whole path, not one turn.
  • Every finding becomes a permanent regression test tied to a retained trace. That's the difference between patched and provably patched.
  • The harness and its tool boundary are part of the system under test. A permission prompt is policy. A sandbox is the boundary. Test both.
  • Mitigation has no finish line. Re-run on every change and on a schedule, so the risk profile is a series, not a snapshot.

This field is younger than it looks. Most of what "good" looks like is still being figured out in public.
